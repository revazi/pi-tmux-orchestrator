# Pi Tmux Orchestrator 0.9.5

Version 0.9.5 fixes attention recovery so an unfinished worker assignment cannot
be masked by steering an idle or unassigned role.

## Breaking change

There is no protocol, command, configuration, database-schema, or authority-model
breaking change in 0.9.5. The stricter send behavior applies only while a
workflow is `needs_attention`: guidance must target a waiting role that still
owns an accepted assignment. Retained runs remain readable.

## Upgrade safely

Finish or stop active orchestrations, update the package, and restart Pi:

```bash
pi update npm:pi-tmux-orchestrator
```

Start a new orchestration after restarting. An already-running broker keeps the
code loaded when that run started and does not hot-reload this correction.

## What changed

- A `needs_attention` send now fails closed unless its target is a waiting role
  that still owns an accepted assignment.
- Sending an idle reviewer or another unassigned role can no longer start an
  unnecessary provider turn or hide the unresolved assignment behind an
  `active` workflow state.
- An accepted reminder no longer marks the workflow active by itself. The
  workflow resumes only after the assigned worker reports lifecycle `active`.
- Parent attention updates include current worker states and identify waiting
  assignment owners explicitly.
- Parent model guidance now prohibits triggering an idle role or reviewer before
  the broker creates its assignment.
- Rejected sends retain bounded metadata-only command records; operator-message,
  assignment, report, provider, and worktree bodies remain outside SQLite,
  status, dashboard, and Supervisor output.

The broker still does not run automatic or unlimited reminder turns. A worker
that settles without `orchestrator_report` remains safely visible as `waiting`
until the operator steers or restarts that assigned role.

## Rollback

If needed, finish or stop active 0.9.5 runs and install the previous exact
version:

```bash
pi remove npm:pi-tmux-orchestrator
pi install npm:pi-tmux-orchestrator@0.9.4
```

Report problems through
[GitHub Issues](https://github.com/revazi/pi-tmux-orchestrator/issues).
