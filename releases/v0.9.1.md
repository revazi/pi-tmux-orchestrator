# Pi Tmux Orchestrator 0.9.1

Version 0.9.1 is a documentation-focused patch that makes the package landing
page substantially shorter and easier to scan. Orchestration behavior is
unchanged from 0.9.0.

## Breaking change

There is no new breaking change in 0.9.1. The 0.9.0 slash-command migration
still applies: use `/or-dashboard`, `/or-models`, `/or-start`, `/or-send`, and
`/or-stop`.

## Upgrade safely

Finish or stop active orchestrations, update the package, and restart Pi:

```bash
pi update npm:pi-tmux-orchestrator
```

Restarting Pi loads the new package version and performs the existing bounded
startup update check. Existing retained manifest v1-v4 runs remain readable;
new runs continue to use manifest v5 and `broker-v1`.

The README was reduced from 1,018 lines and 49.2 KB to 234 lines and 7.7 KB. It

## Update notification

The extension's update notification was already included in 0.9.0. When an
interactive Pi session starts with an older installed version and npm reports a
newer release, it shows a non-blocking warning with:

```text
Update: pi update npm:pi-tmux-orchestrator. Details: /or-dashboard
```

The check is best-effort, time-bounded, skipped in worker/controller sessions,
and disabled with `PI_TMUX_ORCHESTRATOR_DISABLE_UPDATE_NOTICE=1`. Opening the
dashboard does not make another network request.

## Compatibility and safety

The mandatory independent reviewer, one-writer implementer authority, project
instruction discovery, direct worker steering, confirmation boundaries,
authenticated broker transport, metadata-only durable state, and retained-run
compatibility are unchanged.

This release makes no provider-cost savings, billing, or quality-equivalence
claim.

## Rollback

If needed, finish or stop active 0.9.1 runs and install the previous exact
version:

```bash
pi remove npm:pi-tmux-orchestrator
pi install npm:pi-tmux-orchestrator@0.9.0
```

Report problems through
[GitHub Issues](https://github.com/revazi/pi-tmux-orchestrator/issues).
