# Pi Tmux Orchestrator 0.9.3

Version 0.9.3 fixes phased implementer handoffs, prevents phase-union report
schema retries, speeds exact-model startup validation, and makes live worker
activity visible in the broker dashboard before any report handoff.

## Breaking change

There is no orchestration command or authority-model breaking change in 0.9.3.
New runs migrate the metadata-only broker database to schema v8 so live activity
phase and pulse metadata can be retained. Older retained runs remain readable.

## Upgrade safely

Finish or stop active orchestrations, update the package, and restart Pi so every
worker loads the same broker and extension version:

```bash
pi update npm:pi-tmux-orchestrator
```

Do not mix already-running 0.9.2 workers with a newly installed package when
verifying this patch; start a new orchestration after restarting Pi.

## What changed

- The broker now accepts both raw and normalized read-only phased plan envelopes
  while still rejecting implementation, check, finding, limitation, or verdict
  claims during plan assignments.
- Implementer report arguments pass through a bounded compatibility shim before
  validation. Plan-only fields advertised by the shared implementer tool schema
  no longer cause an implementation report retry, while implementation summary,
  changed paths, checks, findings, risks, and limitations are preserved.
- Broker protocol rejections retain the worker request ID instead of surfacing as
  uncertain delivery.
- Shared JavaScript/Python fixtures cover phased plans and implementation,
  reviewer, probe, Playwright, and Django report wire envelopes.
- Startup reuses Pi's in-memory model registry when all exact resolved models are
  already known, with the authoritative CLI model check retained as fallback.
- Workers emit throttled assignment-bound `thinking`, `streaming`, `tool`, and
  `reporting` metadata. The dashboard refreshes immediately and displays a live
  pulse without polling or waiting for handoff.
- Live activity is cleared on settlement, disconnect, and assignment changes.
  Messages, reasoning, tool inputs/results, provider bodies, prompts, diffs, and
  logs remain outside durable broker state and dashboard output.

The mandatory independent reviewer, one-writer implementer authority, project
instruction discovery, confirmation boundaries, authenticated broker transport,
and metadata-only durable-state boundary are unchanged.

## Rollback

If needed, finish or stop active 0.9.3 runs and install the previous exact
version:

```bash
pi remove npm:pi-tmux-orchestrator
pi install npm:pi-tmux-orchestrator@0.9.2
```

Report problems through
[GitHub Issues](https://github.com/revazi/pi-tmux-orchestrator/issues).
