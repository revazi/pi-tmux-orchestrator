# Pi Tmux Orchestrator 0.9.2

Version 0.9.2 removes the package-wide `Ctrl+Shift+G` dashboard shortcut because
it conflicts with Pi's built-in `tui.altScreen.searchPrevious` binding. Open the
orchestration dashboard with `/or-dashboard` instead.

## Breaking change

There is no orchestration protocol or slash-command breaking change in 0.9.2.
The package no longer registers `Ctrl+Shift+G`; users who relied on that shortcut
should use `/or-dashboard`.

## Upgrade safely

Finish or stop active orchestrations, update the package, and restart Pi:

```bash
pi update npm:pi-tmux-orchestrator
```

Restarting Pi loads the new extension version and removes the shortcut-conflict
warning. Existing retained manifest v1-v4 runs remain readable; new runs continue
to use manifest v5 and `broker-v1`.

## What changed

- Removed `pi.registerShortcut("ctrl+shift+g", ...)` from the package extension.
- Kept `/or-dashboard` and all dashboard-local keyboard controls unchanged.
- Added regression coverage that the extension registers no package-wide
  shortcuts.
- Updated the operator reference and refreshed the model-free worker-prompt
  fixture for Pi 0.84.4.

The mandatory independent reviewer, one-writer implementer authority, project
instruction discovery, confirmation boundaries, authenticated broker transport,
and metadata-only durable state are unchanged.

## Rollback

If needed, finish or stop active 0.9.2 runs and install the previous exact
version:

```bash
pi remove npm:pi-tmux-orchestrator
pi install npm:pi-tmux-orchestrator@0.9.1
```

Report problems through
[GitHub Issues](https://github.com/revazi/pi-tmux-orchestrator/issues).
