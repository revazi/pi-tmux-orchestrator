# Pi Tmux Orchestrator 0.11.0

Version 0.11.0 builds on 0.10.0 with opt-in model-guided preflight planning and bounded dynamic topology/model selection. Planning is separate from worker execution: it produces a strict candidate plan, displays a preview, and requires launch confirmation. Without explicit planning opt-in, starts retain the deterministic path.

## Highlights

- Added a shared bounded planning admission path for Pi and terminal starts, binding task/context/configuration/policy/catalog/resources and revalidating before launch. Cancellation, stale previews, invalid plans, and planner failures do not launch workers.
- Added direct TypeSafe Jev decision-model support when configured, with Pi's model registry as the supported fallback path and strict candidate validation. TypeSafe uses the native Pi login flow or `TYPESAFE_API_KEY`; the environment override is stripped before workers launch.
- Added bounded, non-secret model capability metadata for planning, including supported reasoning/thinking, modality, context/output limits and declared catalog rates. Rates are hints, not observed spend or a quality claim.
- Added strict planner preferences, fallback/cancel policy, optional bounded natural-language guidance, and topology constraints; exact per-run/project/profile choices and trusted custom-role contracts remain authoritative.
- Improved parent progress updates with launch-assignment identity and broker dashboard live activity. Report prose does not override authoritative launch metadata.
- Hardened broker report validation and retained body-free planning provenance.

## Migration

Install/update with `pi update npm:pi-tmux-orchestrator` or `pi install npm:pi-tmux-orchestrator`. Finish or stop active runs before changing package versions. No configuration is required for ordinary starts. Dynamic planning is opt-in and makes one additional decision-model call after explicit approval; preview and final launch confirmation remain separate. TypeSafe setup and planner configuration are documented in the [usage guide](../references/usage.md).

The five-command surface remains `/or-dashboard`, `/or-models`, `/or-start`, `/or-send`, and `/or-stop`. Existing retained runs remain readable; new ordinary manifests use v5 and explicit custom-role runs use v7, both with `broker-v1`. The supported worker adapter baseline is Pi 0.87.1, Python 3.11+, and tmux 3.2+ (3.5+ recommended).

## Safety and limits

Planning inputs and candidate metadata are bounded and validated; no worker starts before admission and confirmation. Broker state remains metadata-only. Direct Jev transport is fixed-endpoint and fail-closed, with no retries or raw provider errors retained. No provider quality, cost-saving, or production acceptance claim is made by these changes or provider-free tests. See [security policy](../SECURITY.md) and [prerelease workflow](../references/prerelease-testing.md).

## Rollback

If migration fails, finish or stop active runs, remove the updated package, and reinstall the exact prior version:

```sh
pi remove npm:pi-tmux-orchestrator
pi install npm:pi-tmux-orchestrator@0.10.0
```

Restart Pi after installation. Do not resume an in-flight run across package versions. Prior retained runs remain readable, but keep their original environment until safely stopped or finished. Refer to the [0.10.0 release notes](v0.10.0.md) for prior behavior and configuration.
